Inside the workspace

for Infinni

Part 2 of taking a design org AI-first

In Part 1 I said design tools were always proxies. This is what we design in instead.

A workspace is one folder per feature. Everything about that feature lives in it: the brief, the inspiration, every decision, the flows, the prototype, the copy and the handoff. Code sits in the middle. Everything else points at it.

Six places, six truths

Think about where a feature lives today. The design file. The PRD. The specs. The tickets. A moodboard somewhere. And the Slack threads where the real decisions got made.

Six places. Six versions of the truth. And someone whose actual job is keeping them in sync, which nobody ever fully does.

That’s not a tooling problem. It’s a structure problem. As long as the work is split across artefacts, it drifts.

So we put it all in one place, and made code the thing in the middle.

Designers don’t open it

The first thing people assume: designers now live in a code editor. They don’t.

A designer opens Claude and says start a workspace for the link-in-bio page. Claude sets it up and hands back a link. From then on it’s plain language. Save my work. Send it for review. Open the PM’s branch. There are no commands to remember.

Under the hood it’s all Git. Branches, commits, pull requests. Claude runs it, signed in as the designer. They never clone a repo or type a command.

The workspace app itself has no chat. That’s deliberate. You prompt in your own Claude. The workspace is what you build, not where you talk.

A tour

Every workspace runs the same app. Six tabs.

Mood. Inspiration from real products, pulled by an agent on request. Every picture keeps its source.

Prototype. Not a mockup. The real UI, in code, built from the design system. It updates live while Claude works.

The Debug drawer is where it gets interesting. Switch the state. Slow the network to three seconds. Fail a request. Go offline. Designers used to skip the unhappy paths because nobody could see them. Now they’re two clicks away, so they get designed.

Flows. Every screen in the feature, including the ones nobody has designed yet. Those show as placeholders, so the flow is complete from day one. Each screen has a status: Pending, Building, Ready for dev. Ready can’t be claimed. A screen only gets there with a story, a test and approved copy, and a check confirms it.

Provenance. Every choice, inspiration and decision, in the designer’s own words, linked to the screens it shaped.

This is the tab I’m proudest of. “Why does it look like this?” used to live in someone’s head, and left when they did. Now it sits beside the screen, for every reviewer and every engineer who comes later.

Copy. Every string in the feature, edited in context. Our UX writer works here, with their own Claude, and proposes changes like anyone else. No copy decks. No pasting text into tickets.

Handoff. A spec, screen by screen, generated from the code and the flows.

The page says it best: nothing is hand-written, so it can’t drift. A handoff used to be a document someone wrote at the end. Here it’s a view of what’s already true.

Sharing is a sentence

Save my work pushes a work-in-progress branch. A PM asks their own Claude to open it, and clicks through the real thing on their own machine. No export. No “latest-final-v3”. No meeting to walk through it.

When it’s ready, send it for review opens a pull request. An agent writes the summary, so the reviewer knows what to read and what to skip. The checks run. A person greenlights it. Nothing merges on an agent’s say-so.

Next up: comments right on the prototype. Click an element, leave a note, and it’s stored with the exact build, screen and state the reviewer saw. Claude can rebuild that view exactly. No more screenshots in threads.

What it asks of designers

This isn’t free. It asks designers to change how they think about the job.

  • You ship code, not pictures. A design file is input, not the deliverable.
  • You describe and judge. Claude does the typing.
  • Share early, in small steps. Save before it’s perfect.
  • A red check is a fact about the code, not a verdict on you.
  • Write down why. If it shaped the design, it goes in provenance.

The last one is the hardest. Designers are used to the “why” being obvious to everyone in the room. A workspace outlives the room.

For other design leaders

Don’t give your designers a better design tool. Give them one place where the work lives, and put code in the middle of it.
